# zapret2: как подбирать стратегии обхода ТСПУ

Документ для человека или агента, которому нужно починить прямой (без прокси)
доступ к сайтам из `module/zapret2/hosts.txt`. Что такое zapret2 в этой
конфигурации и чего он не делает — в шапке `module/zapret2.nix`.

## Коротко

```
just zapret-check        # что сейчас не открывается напрямую (без root, ничего не меняет)
just zapret-tune         # подобрать стратегии заново, записать profiles.json
just switch              # применить
```

Во время `just zapret-tune` не запускать `just switch`: он поднимет службу,
замеры смешаются, скрипт прервётся.

## Файлы

| Файл | Что это | Кто правит |
|---|---|---|
| `module/zapret2/hosts.txt` | домены, для которых нужен обход | человек |
| `module/zapret2/candidates.txt` | стратегии-кандидаты по приоритету | человек |
| `module/zapret2/probe-hosts.txt` | необязательный: какой хост проверять вместо `домен` и `www.домен` | человек |
| `module/zapret2/profiles.json` | какая группа доменов какой стратегией обходится | только `just zapret-tune` |
| `scripts/zapret2-tune.sh` | подбор | — |
| `module/zapret2.nix` | собирает из `profiles.json` конфиг nfqws2 | — |

## Главное, что нужно знать

**Одной стратегии на все домены нет.** Стратегия, которая чинит один сайт,
ломает другой, в том числе незаблокированный. Замеры 2026-11-16 на этой сети:

- Кэшам YouTube у провайдера (`rrN---sn-*.googlevideo.com`) фальшивый
  ClientHello ломает TLS, работает только нарезка без фальшивки.
  Симптом был: youtube.com открывается, видео не грузится.
- Discord и X наоборот: без фальшивки не открываются.
- Старый конфиг применял фальшивку ко всему списку и этим ломал сайты, которые
  открываются вообще без обхода (например, `mozilla.org`: 0 из 10 с обходом).
- Большинство доменов списка (185 из 281) открываются без обхода вовсе.

Поэтому подбор идёт по каждому домену отдельно, а результат — несколько
профилей nfqws2, каждый со своим списком доменов.

**Проверять нужно тот хост, который реально блокируют.** У CDN витрина и узлы
раздачи блокируются по-разному: `www.youtube.com` открывался, а видеосервер нет.
Для YouTube скрипт сам узнаёт имя кэша провайдера (спрашивает у
`redirector.googlevideo.com/report_mapping` и переводит код площадки в
`sn-`имя). Для других CDN — вписать узел в `probe-hosts.txt`:

```
# домен  хост [хост...]
discord.media  some-node.discord.media
```

Как узнать узел: открыть сайт через прокси, в DevTools → Network посмотреть,
с какого хоста идёт то, что не грузится.

**Сеть шумит под нагрузкой.** Десятки параллельных запросов к заблокированным
адресам дают ложные отказы: при 32 потоках «не открывались» Discord и YouTube,
которые через пять минут открывались 6 раз из 6. Поэтому в скрипте 4 потока и
двойная перепроверка упавших. Отдельным замерам верить только после повтора; сомнение
проверяется руками, по одному запросу:

```
for i in 1 2 3 4 5 6; do
  curl -4 -s -o /dev/null --noproxy '*' --max-time 4 -w '%{http_code} ' https://ХОСТ/
done
```

`000` — TLS не прошёл. Любой другой код, включая 403/404, значит «не заблокировано».

## Что делает `just zapret-tune`

1. Останавливает службу, поднимает свою таблицу nft и свою очередь (не
   пересекается со службой), берёт nfqws2 и lua из установленного юнита.
2. Проход без обхода: какие домены открываются и так. Они получают группу
   `direct`, zapret их не трогает, стратегии на них не проверяются.
3. Из закрытых отсеивает имена, где на tcp/443 никто не отвечает (сайта нет
   или блокировка по IP) — стратегия им не поможет.
4. По очереди каждую стратегию из `candidates.txt`: запускает nfqws2 с ней одной
   на весь tcp/443 и проверяет закрытые домены, которым стратегия ещё не
   найдена. Домен получает первую подошедшую.
5. Закрытые, которым ничего не помогло, — `unknown`; остаются в профиле первой
   стратегии. Обычно это имена без сайта (`ytimg.com`, `twimg.com` — живут
   только поддомены), реже блокировка по IP или нужна стратегия не из списка.
6. Контроль: поднимает все профили разом, как это сделает служба, и проверяет
   ещё раз. Строки `НЕ ПРОШЁЛ` в отчёте — повод разобраться до `just switch`.
7. Пишет `profiles.json`, возвращает службу в прежнее состояние.

Прогон 2026-11-16: 281 домен, около 12 минут. 185 открыты без обхода, 22 не
отвечают на tcp/443, из оставшихся 74: `fake-md5-disorder` — 24,
`disorder` — 11, `tcpseg` — 11, без решения — 28.

Критерий «открывается» — завершённый TLS-handshake напрямую, по IPv4. Скорость
после handshake скрипт не меряет: замедление (а не блокировку) он не увидит.
Если сайт открыт, но тормозит и обход ему помогает, — его нужно вписать в
`profiles.json` руками, скрипт отнесёт его к `direct`.

### Почему открытые сайты не трогаем

Первая версия подбора назначала стратегию всем доменам. Отказались:

- обход им не нужен, а навредить может: фальшивый ClientHello ломал сайты,
  которые без него открывались;
- замеры открытых сайтов под стратегиями не воспроизводились: одной и той же
  стратегии в четырёх прогонах «подходило» 106, 142, 203 и 147 доменов.
  Проход без обхода при этом стабилен (160–193 из 281);
- их таймауты под неподходящей стратегией растягивали прогон за полчаса.

## Если ни один кандидат не подошёл

Домен в `unknown`, но сайт точно существует и через прокси открывается.

1. Убедиться, что это не блокировка по IP — тогда zapret бессилен, нужен тоннель:

   ```
   ping -c2 ХОСТ
   curl -4 -s -o /dev/null --noproxy '*' --max-time 5 -w '%{http_code}\n' http://ХОСТ/
   ```

   TCP на 443 не соединяется вовсе (`time_connect` = 0) — блокировка по адресу.
   Соединяется, но TLS не проходит — блокировка по содержимому, zapret может помочь.
2. Полный перебор: `just zapret-blockcheck ХОСТ`. В конце печатает рабочие
   наборы `--lua-desync=...`.
3. Выбрать самый простой из рабочих, дописать строкой в `candidates.txt`
   (ниже существующих, чтобы не менять раскладку остальных), повторить
   `just zapret-tune`.

Гипотезу о конкретной стратегии можно проверить без перебора — так была
найдена причина с YouTube: взять рабочую для большинства стратегию, убрать или
заменить в ней одну часть, сравнить на двух хостах с разным поведением.

## Чего здесь нет

- **QUIC (udp/443).** На 2026-11-16 напрямую не проходил никуда, включая
  домены вне списка; профиль `quic` в модуле не подбирался. Браузер откатывается
  на TCP.
- **Не-443 и не-TLS.** Голос Discord, Telegram MTProto и т. п. под правила не
  попадают.
- **Трафик через прокси.** zapret видит только то, что уходит с ноутбука
  напрямую; соединения sing-box к серверам тоннелей исключены в nft.
