# Миграция корневого раздела на LUKS2 (in-place, без переустановки)

Инструкция для исполнителя (человека или ИИ-агента), который будет проводить операцию.

**Целевая машина: `yoga14`** (Lenovo Yoga). Задача: зашифровать существующий
корневой раздел **на месте**, сохранив все данные, без переразметки и
переустановки системы.

> **Внимание, источник путаницы.** Каталог репозитория называется
> `my-nix-config-huawei`, но это общий конфиг на несколько машин. Целевой хост —
> **`yoga14`**, его конфигурация лежит в `devices/yoga14/`. Каталог
> `devices/huawei-rlef-x/` — **другая машина, не трогать**.

> **Плейсхолдеры.** В тексте специально не указаны конкретные значения, они
> подставляются перед выполнением:
>
> | Плейсхолдер | Где взять |
> |---|---|
> | `ROOT-FS-UUID` | `blkid /dev/nvme0n1p2` — UUID ext4 корня |
> | `EFI-UUID` | `blkid /dev/nvme0n1p1` — UUID vfat раздела `/boot` |
> | `BACKUP_HOST` | адрес хоста-приёмника бэкапа (проводной интерфейс) |
> | `BACKUP_HOST_WIFI` | его же адрес по Wi-Fi |
>
> Актуальные UUID этой машины — в `devices/yoga14/hardware-configuration.nix`.

> **Читай целиком до начала.** Операция необратима в середине процесса.
> Шаги 3.3–3.5 нельзя прерывать «на подумать» — только доводить до конца
> или откатывать по процедуре из раздела 8.

## 1. Исходное состояние железа

Проверено на живой системе `yoga14` через `findmnt`.

| Параметр | Значение |
|---|---|
| Хост | `yoga14` |
| Конфигурация в flake | `nixosConfigurations.yoga14` |
| Каталог устройства | `devices/yoga14/` |
| Диск | `/dev/nvme0n1`, 953,9 GiB, NVMe |
| EFI-раздел | `/dev/nvme0n1p1`, vfat, 499 MiB, UUID **`EFI-UUID`**, точка монтирования `/boot` |
| Корень | `/dev/nvme0n1p2`, ext4, 937,3 GiB, UUID **`ROOT-FS-UUID`**, точка монтирования `/` |
| Занято на корне | ~773 GiB из 938 GiB (свободно ~117 GiB) |
| Swap | **только zram** (`zram0`, 15,4 GiB); в конфиге `swapDevices = []` — уже корректно |
| CPU | Intel Core Ultra 7 258V (есть AES-NI — шифрование аппаратное) |
| TPM | Присутствует (`/sys/class/tpm/tpm0`) |
| Загрузчик | `systemd-boot` (см. `configuration.nix:148`) |

Схема разделов после операции **не меняется**: те же два раздела, тот же порядок,
тот же размер. Меняется только содержимое `nvme0n1p2` — поверх него появляется
контейнер LUKS2, а ext4 уезжает внутрь него со сдвигом на 32 MiB.

**Важное следствие:** UUID файловой системы ext4 (`ROOT-FS-UUID`) **не меняется**,
потому что сама ФС не пересоздаётся. В конфиге строку `fileSystems."/"` править
не нужно. Появляется только **новый** UUID — у LUKS-контейнера, его узнаем на шаге 3.6.

### Фаза 1. Подготовка флешки

Записать образ **NixOS minimal ISO** (версия не старше текущей системы —
нужен `cryptsetup` ≥ 2.4 с поддержкой LUKS2 reencrypt; система на
`nixos-26.05`):

```bash
sudo dd if=nixos-minimal-*.iso of=/dev/sdX bs=4M status=progress conv=fsync
```

Флешку **не вынимать** до полного завершения операции — если что-то пойдёт не
так на фазе 4 или 5, чинить придётся с неё.

### Фаза 2. Загрузка с флешки

2.1. Загрузиться с USB, выбрать в меню обычный live-режим.

2.2. Стать root и убедиться, что целевой раздел **не смонтирован**:

```bash
sudo -i
lsblk -f
```

`/dev/nvme0n1p2` не должен иметь точки монтирования. Если live-система
примонтировала его автоматически — `umount /dev/nvme0n1p2`.

> **Осторожно:** в live-окружении имена дисков могут отличаться. Проверь по
> UUID, что работаешь именно с тем разделом:
> ```bash
> blkid /dev/nvme0n1p2
> ```
> Ожидается `UUID="ROOT-FS-UUID" TYPE="ext4"`.
> Если UUID не совпал — **остановись** и найди правильное имя устройства.

### Фаза 3. Шифрование

#### 3.1. Проверка файловой системы

```bash
e2fsck -f /dev/nvme0n1p2
```

Обязательно с `-f` (принудительно, даже если ФС помечена чистой). Если найдены
ошибки — исправить и прогнать повторно, пока не будет чисто. **Не переходить
дальше с ошибками ФС.**

#### 3.2. Ужать файловую систему на 64 MiB

LUKS2-заголовку нужно место в начале раздела. `cryptsetup` сдвинет данные, но
освободить хвост ФС должен ты. Берём 64 MiB — вдвое больше необходимых 32 MiB,
для запаса.

```bash
BSIZE=$(dumpe2fs -h /dev/nvme0n1p2 2>/dev/null | awk -F: '/^Block size/{print $2}' | tr -d ' ')
BLOCKS=$(dumpe2fs -h /dev/nvme0n1p2 2>/dev/null | awk -F: '/^Block count/{print $2}' | tr -d ' ')
echo "block size=$BSIZE, blocks=$BLOCKS"

NEW=$(( BLOCKS - 64*1024*1024/BSIZE ))
echo "new block count=$NEW"

resize2fs /dev/nvme0n1p2 $NEW
```

При размере блока 4096 это отнимет 16384 блока. Операция быстрая — свободного
места 117 GiB, реальные данные двигать не придётся.

#### 3.3. Перешифровка (основной шаг)

```bash
cryptsetup reencrypt --encrypt --type luks2 \
  --reduce-device-size 32M \
  /dev/nvme0n1p2
```

Спросит подтверждение и **новый пароль** — дважды.

**О пароле:** в initrd раскладка клавиатуры US. Использовать только ASCII без
кириллицы; избегать символов, которые смещаются между раскладками. Пароль
записать до ввода — восстановить его невозможно.

Идёт ~40–60 минут, показывает прогресс. Читает и переписывает весь раздел.

> **Если процесс прервался** (питание, случайный `Ctrl+C`): не паниковать.
> LUKS2 ведёт журнал в заголовке. Продолжить:
> ```bash
> cryptsetup reencrypt --resume-only /dev/nvme0n1p2
> ```

#### 3.4. Открыть контейнер

```bash
cryptsetup open /dev/nvme0n1p2 cryptroot
```

Появится `/dev/mapper/cryptroot`.

#### 3.5. Вернуть файловой системе полный размер

```bash
e2fsck -f /dev/mapper/cryptroot
resize2fs /dev/mapper/cryptroot
```

Без указания размера `resize2fs` растянет ФС на весь доступный объём контейнера.

#### 3.6. Бэкап заголовка — НЕ ПРОПУСКАТЬ

```bash
cryptsetup luksHeaderBackup /dev/nvme0n1p2 \
  --header-backup-file /root/luks-header-yoga14.img

# Узнать UUID контейнера — понадобится для конфига на фазе 4:
cryptsetup luksUUID /dev/nvme0n1p2
```

**Записать этот UUID.** Формат — как обычный UUID, например
`1a2b3c4d-5e6f-7890-abcd-ef1234567890`. Это UUID **LUKS-контейнера**; он не имеет
отношения к UUID ext4 внутри него (`ROOT-FS-UUID`) и не равен ему.

Скопировать заголовок минимум в два места вне ноутбука:

```bash
# на флешку (примонтировать её отдельно)
cp /root/luks-header-yoga14.img /mnt/usb/

# на стационарник
scp /root/luks-header-yoga14.img bg@BACKUP_HOST:/home/bg/backup-huawei-meta/
```

> Файл заголовка содержит зашифрованные ключевые слоты. Тот, у кого есть и
> заголовок, и пароль, получает данные. Хранить не публично.

### Фаза 4. Правка конфигурации NixOS

Выполняется **после** шага 3.6, до перезагрузки, из live-окружения.

#### 4.1. Смонтировать систему

```bash
mount /dev/mapper/cryptroot /mnt
mount /dev/nvme0n1p1 /mnt/boot
```

#### 4.2. Отредактировать `hardware-configuration.nix`

Файл: `/mnt/home/bg/Documents/code/github.com/back2nix/nix/my-nix-config-huawei/devices/yoga14/hardware-configuration.nix`

**Каталог `devices/yoga14/`, не `devices/huawei-rlef-x/`.**

**Изменение — добавить LUKS-устройство.** Вставить после блока
`boot.extraModulePackages`:

```nix
  boot.initrd.luks.devices."cryptroot" = {
    device = "/dev/disk/by-uuid/ВСТАВИТЬ-UUID-ИЗ-ШАГА-3.6";
    allowDiscards = true;
  };
```

`allowDiscards = true` включает TRIM на SSD — без него со временем деградирует
производительность записи. Плата: наружу «просвечивает», какая доля раздела
занята данными. Для ноутбука это приемлемый размен; если нужен максимум
скрытности — убрать эту строку.

**Что НЕ трогать:**

- `fileSystems."/"` с UUID `ROOT-FS-UUID` — оставить
  как есть. ext4 внутри контейнера та же самая, UUID не меняется. Соблазн
  «поправить UUID» приводит к незагружающейся системе.
- `fileSystems."/boot"` с UUID `EFI-UUID` — не меняется, раздел остаётся
  незашифрованным.
- `swapDevices = []` — уже корректно, отдельного swap-раздела нет, только zram.

#### 4.3. Проверить модули initrd

В `boot.initrd.availableKernelModules` у `yoga14` уже есть `nvme` — этого
достаточно, чтобы initrd увидел диск. Модули `dm_crypt`/`aes` NixOS подтягивает
автоматически при наличии `boot.initrd.luks.devices`. Дополнительно ничего
добавлять не нужно.

### Фаза 5. Пересборка системы

```bash
nixos-enter --root /mnt
```

Внутри chroot:

```bash
cd /home/bg/Documents/code/github.com/back2nix/nix/my-nix-config-huawei
nixos-rebuild boot --flake .#yoga14
```

**Имя конфигурации — `yoga14`.** Не `huawei`.

`boot`, а не `switch` — новая конфигурация ставится загрузочной, но не
применяется к текущему (live) окружению. Это то, что нужно.

> **Если сборке нужна сеть,** а её в chroot нет: выйти, настроить сеть в
> live-окружении (`nmcli`/`wpa_supplicant`), затем зайти снова. Большинство
> зависимостей уже в `/nix/store` на диске, и сборка может пройти офлайн.
>
> **Если git ругается на dubious ownership:**
> ```bash
> git config --global --add safe.directory /home/bg/Documents/code/github.com/back2nix/nix/my-nix-config-huawei
> ```

Выйти из chroot (`exit`), размонтировать:

```bash
umount -R /mnt
cryptsetup close cryptroot
```

Перезагрузиться, **вынуть флешку** только после успешной загрузки.

### Фаза 6. Проверка результата

После перезагрузки система должна запросить пароль на раннем этапе загрузки.
После входа проверить:

```bash
lsblk -f          # nvme0n1p2 -> crypto_LUKS, внутри cryptroot -> ext4 /
df -h /           # объём совпадает с прежним (~937G)

findmnt -no SOURCE,UUID /   # должно быть /dev/mapper/cryptroot, UUID ROOT-FS-UUID
```

Данные на месте, домашний каталог цел, система работает как раньше.

## 6. Опционально: автоматическая разблокировка через TPM2

**Делать только после того, как загрузка с паролем подтверждённо работает.**
Сначала должен быть надёжный путь, автоматика — сверху.

```bash
systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=0+7 /dev/nvme0n1p2
```

Плюс в конфиг:

```nix
  boot.initrd.systemd.enable = true;
```

(TPM2-разблокировка требует systemd-initrd.)

Пароль остаётся рабочим как запасной путь. PCR 0+7 привязывают ключ к прошивке
и состоянию Secure Boot — при обновлении UEFI разблокировка сломается и
понадобится пароль с последующим перезаписыванием слота.

**Компромисс, который нужно понимать:** TPM без PIN означает, что укравший
включённый ноутбук получит расшифрованный диск автоматически. TPM защищает от
выемки диска, но не от кражи целого устройства. Если это существенно — добавить
`--tpm2-with-pin=yes`.

## 7. Что НЕ входит в эту операцию

- **`/boot` остаётся незашифрованным.** Это требование UEFI: ядро и initrd
  должны читаться до всякого LUKS. Защита от подмены ядра — это Secure Boot
  со своими ключами (`lanzaboote` на NixOS), отдельная задача.
- **Гибернация не настраивается.** Swap только zram, отдельного раздела нет.
- **Переразметка не производится.** Схема разделов остаётся прежней.
- **Другие машины из репозитория** (`huawei-rlef-x`, `asus-ux3405m`, `desktop`)
  не затрагиваются.

## 8. Откат и аварийные ситуации

### Система не загружается после перезагрузки

Загрузиться с флешки, открыть контейнер вручную и войти в систему:

```bash
cryptsetup open /dev/nvme0n1p2 cryptroot
mount /dev/mapper/cryptroot /mnt
mount /dev/nvme0n1p1 /mnt/boot
nixos-enter --root /mnt
```

Проверить конфиг (частая причина — опечатка в UUID из шага 3.6), пересобрать,
выйти, перезагрузиться.

> **Старые поколения в меню `systemd-boot` не спасут.** Они не знают про LUKS
> и загрузиться не смогут — рабочим будет только новое поколение. Привычный
> рефлекс «откачусь на предыдущее» здесь не работает.

### Забыт пароль / повреждён заголовок

Восстановить заголовок из бэкапа:

```bash
cryptsetup luksHeaderRestore /dev/nvme0n1p2 \
  --header-backup-file /path/to/luks-header-yoga14.img
```

Если пароль забыт безвозвратно — данные потеряны, остаётся восстановление
из бэкапа домашнего каталога (раздел 2.1) на свежеустановленную систему.

### Полный откат к незашифрованному диску

LUKS2 умеет обратную операцию:

```bash
cryptsetup reencrypt --decrypt /dev/nvme0n1p2
```

После неё вернуть `devices/yoga14/hardware-configuration.nix` в исходное
состояние (`git checkout`) и пересобрать. Файловая система останется на 64 MiB
меньше раздела — это безвредно, при желании растягивается через `resize2fs`.

### Восстановление домашнего каталога из бэкапа

```bash
rsync -aAXH --numeric-ids --info=progress2 \
  -e "ssh -c aes128-gcm@openssh.com" \
  bg@BACKUP_HOST:/home/bg/backup-huawei/ /home/bg/
```

Помнить: Docker-образы и кэши в бэкап не входили — они пересоздаются сами.
