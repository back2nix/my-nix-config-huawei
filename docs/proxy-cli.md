# CLI через выбранный прокси

Команды `claude`, `codex`, `kimi`, `gcloud` устанавливаются с суффиксами
`-1082`, `-1088`, `-1090`, например `claude-1088` и `codex-1090`.
Старые команды `*-china` удалены. Gemini пока отключён в списке пакетов.

В fish команда `claude` по умолчанию запускает `claude-1090-safe` (фиксированная Astana).
Выбор сохраняется через универсальную переменную fish, без пересборки:

```fish
claude-proxy        # показать выбор
claude-proxy 1088   # выбрать пару 1088/1089
claude-proxy 1091   # выбрать пару 1090/1091; принимаются оба порта пары
claude
```

Аналогично `codex` запускает `codex-1082-safe` (фиксированный Сеул, пара USA). Его выбор независим
от Claude и также сохраняется между терминалами:

```fish
codex-proxy        # показать выбор
codex-proxy 1088   # выбрать пару 1088/1089
codex-proxy 1082   # вернуть пару USA 1082/1083
codex
```

Все сокращения `claude` и `codex` запускают safe-обёртки с изолированной сетью.
Каждая поддерживает `--check`: `claude --check`, `codex --check`.
Codex всегда запускается с `--no-daemon`, чтобы не передать работу серверу
вне изоляции. Обычные команды с суффиксом без `-safe` остаются доступны явно.

| Safe-пара | Вход на хосте | Фиксированный выход |
| --- | --- | --- |
| 1082 | 1093 | Сеул |
| 1088 | 1095 | Франкфурт |
| 1090 | 1097 | Astana |

Отдельная команда [`claude-1082-safe`](claude-safe.md) изолирует IP-сеть,
сохраняет доступ к локальному k3s и использует фиксированный Сеул через
выделенный вход 1093. Все safe-команды не следуют переключателю `proxy-mode`.

| Суффикс | SOCKS-вход | HTTP-вход | Переключение маршрута |
| --- | --- | --- | --- |
| -1082 | 1082 | 1083 | `proxy-mode <режим>` |
| -1088 | 1088 | 1089 | `proxy-mode --1088 <режим>` |
| -1090 | 1090 | 1091 | `proxy-mode --1090 <режим>` |

Обёртки используют HTTP для совместимости, в частности Claude Code
не поддерживает SOCKS. Для HTTPS-запроса клиент передаёт доменное имя
HTTP-прокси посредством CONNECT, затем sing-box разрешает его.

DNS целевых доменов каждой пары отправляется в Quad9 по DoH через тот же
selector, что и соединение. IP DNS-сервера задан явно, TLS проверяется
для `dns.quad9.net`. Для этих входов отключено кеширование DNS, чтобы
после переключения маршрута не использовать ответы прежнего выхода.
В режиме `direct` и DNS, и соединение выходят без VPN.

Для клиентов с поддержкой SOCKS используйте `socks5h`:

```sh
curl --proxy socks5h://127.0.0.1:1088 https://example.com
```

В curl `socks5h` передаёт доменное имя прокси, а `socks5` разрешает его
локально. Настройки sing-box не отменяют DNS-запросы, которые клиент
самостоятельно отправил до обращения к прокси. Системный DNS через
blocky/dnscrypt-proxy остаётся отдельным и использует вход 1082.

Проверки: Nix eval конфигурации и 12 команд, sing-box 1.13.14 check
с временными SSH-реквизитами, изолированная проверка маршрутизации
всех шести SOCKS5h/HTTP-входов через локальные тестовые HTTP-прокси.
Соединения с реальными SSH-серверами этой проверкой не проверялись.
